## Context

The HUD is React (`apps/game/src/ui`, about 2,300 lines) styled by four CSS files
(about 3,000 lines) with Barlow, Barlow Condensed and Cinzel from Fontsource,
and icons from `lucide-react` (about 30 imports plus an order icon map of about
30 entries in `ui/hud/orderMeta.ts`) and one custom SVG (`HudIcons.tsx`).
The compendium (`CodexPanel.tsx`) lists `FIGURES` from `packages/content`.
The 3D scene and its pixel post-process are untouched by this change; the
simulation/presentation boundary does not move.

## Goals / Non-Goals

**Goals:** one coherent pixel interface over the low-poly scene; original,
non-repeating period icons that the user can edit in Aseprite; a compendium
that reads like a field book and shows only sourced entries; nothing harder
to read than today.

**Non-Goals:** low-resolution rendering of the whole UI, the 3D art pass,
new historical research, mobile layouts.

## Decisions

### Visual tokens

`styles/pixel.css` defines the tokens once: palette (ink #1b140d, panel
#2a1f14, panel-raised #3a2b1b, parchment #efe2c4, parchment-dim #c9b68f, gold
#e0b85a, gold-dim #a8873f, red #a3473a, olive #6f7a3e, disabled #6b6152), the
2 px unit, border and shadow recipes. Panels use a 2 px solid border plus a
stepped corner built with `clip-path: polygon(...)` in 2 px steps (no
`border-radius`), and a hard `box-shadow: 2px 2px 0` offset (no blur).
Buttons have pressed (1 px inset) and focus (2 px gold outline, offset 2 px)
states. Text uses Pixelify Sans at 12, 14, 16, 20 and 32 px only (the sizes
where the font's grid stays crisp); `-webkit-font-smoothing: none` where the
browser honours it. The CSS files are consolidated around these tokens; dead
rules found on the way are removed.

### Icons from Aseprite

`assets/icons/prestes-icons.aseprite` holds one 16 x 16 cel per icon on a
single sprite, with a named slice per icon (`order-attack`, `stance-prone`,
`ui-codex`, ...). The first version is generated by a Lua script
(`tools/icons/build-icons.lua`, run with `Aseprite.exe -b --script`), which
draws each icon from a small text grid so the drawings are reviewable in
the repository; afterwards the `.aseprite` file is the source and the user
can redraw any icon. `pnpm icons` (`tools/export-icons.ts`) runs
`Aseprite.exe -b prestes-icons.aseprite --split-slices --sheet
apps/game/src/assets/icons.png --data apps/game/src/assets/icons.json`.
Both exported files are committed; the build and tests never need Aseprite.

In the game, `PixelIcon` renders a `span` with the sheet as a CSS mask
(`mask-image`, `mask-position` from the JSON slice) and `background:
currentColor`, so icons follow the button's colour states, scaled by whole
numbers with `image-rendering: pixelated`. A unit test checks that every
order, posture, stance and HUD control in the icon map has a slice, that no
two controls share a slice, and that the JSON and the PNG agree.

### Floating windows

A `FloatingWindow` component (title bar with grip, title and minimize button,
pixel frame) wraps each of the three HUD windows. Dragging uses pointer events
on the title bar with pointer capture; the window is clamped inside the
viewport (re-clamped on resize) and snaps to the 2 px grid. Minimizing keeps
only the title bar. Positions and minimized flags are stored per window in
`localStorage` (`prestes.hud.windows.v1`), read and written in try/catch so a
blocked storage only loses the layout; defaults place Orders bottom centre,
Troops bottom left and Troop summary above Troops, clear of the training
panel on the right. Windows never cover the top bar; clicks on a window never
reach the map. Keyboard: the minimize button is a real button; a window can be
moved with the arrow keys while its title bar has focus.

- **Orders** reuses the order board content (fire, movement, troop groups,
  postures, stances, Hold Fire, bounding, clear) in a compact grid.
- **Troops** lists the player's troops (squad cards with name and living
  count) and keeps box and click selection on the map unchanged.
- **Troop summary** shows, for the selected troop, one `unit-helmet` per
  soldier in a wrapping row; under each helmet three 3 x 14 px vertical bars
  (health, morale, ammunition as magazine plus reserve over the full load).
  Helmet colour: parchment fit, gold selected, red wounded, dim incapacitated,
  dark dead; a tooltip names the soldier's state, fatigue and wound. Below:
  the weapon line, cover and cohesion, as in the current weapon card.

### Start screen photograph

At build time nothing changes: the component draws the existing WebP into a
small canvas (320 px wide), maps it to an 8-colour sepia palette with ordered
dithering, and shows that canvas scaled up with `image-rendering: pixelated`.
This keeps one source image and makes the treatment adjustable.

### Compendium registry

`packages/content/src/compendium.ts` exports `COMPENDIUM` with four sections.
Entries: `{ id, section, titleKey, bodyKey, sourceRefs, confidence, date?,
labels }`. Figures are the existing registry; events come from
`docs/history/TIMELINE.md` (one entry per row, with its confidence); places
are the ones named in those events (Vila Militar / Deodoro, Forte de
Copacabana, Foz do Iguaçu, Serra Nova, Pantanal, La Gaiba...); weapons come
from `docs/history/WEAPONS.md`. Validation fails on an entry without a source
or confidence. The book UI has tabs, a list and a reading page with the source
line and confidence badge; the known corrections are a page of their own.

## Risks / Trade-offs

- Pixel fonts are wider than Barlow Condensed: some HUD labels may overflow.
  Mitigation: the HUD e2e and visual tests at 1440 x 900 and a manual check at
  929 px; abbreviations live in the locale catalogs, not in code.
- Mask icons need `mask-image` (supported by current Chromium, Firefox and
  Safari). The `HudIcons` fallback is removed only once the mask renders in
  the e2e browser.
- Visual baselines change entirely; they are re-recorded after a manual review
  of each screen.

## Migration Plan

Old fonts and Lucide are removed in the last task, after every component uses
the new tokens and icons, so the build stays green between tasks.
